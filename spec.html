2. 后台状态与每种状态的页面入口

列表默认显示全部样例状态。下表中的“详情”都使用只读排版；只有允许编辑的状态有编辑页面。列表和详情复用同一动作映射，禁止通过详情绕过状态限制。核验和取消还取决于关联活动状态。

活动的主链路

草稿 → 待审核 → 报名中 → 已满或报名截止 → 进行中 → 已结束。审核不通过 → 未通过 → 修改后待审核。报名中、已满、报名截止可取消 → 已取消。已满状态因取消报名释放名额可回到报名中，但不能越过截止时间。

生产环境中，报名截止、开始、结束按服务端时间推进；本原型冻结演示时点并用不同样例呈现状态，不使用真实时钟自动改变测试数据。活动结束后，待参加记录改为未到场；已到场记录保持不变。

其他主链路

  • 任务与新人活动：草稿 → 进行中 → 已结束。结束为终态，需要再次开展时新建，不把历史活动改回进行中。
  • 福利：草稿 → 已上架 → 已兑完；补货后恢复已上架；已上架／已兑完 → 已下架 → 编辑并重新上架。
  • 兑换：待使用 → 已使用／已过期／已退回，均为终态；不得重复核销或退回。
  • 贡献：草稿 → 待审核 → 已采纳／未采纳；未采纳修改后可再次提交。
  • 管家：待审核 → 已通过／未通过；未通过可修改重提，已通过可退出。

4. 业务规则与待确认项

环节规则上线前确认
新人领取本人完成生活知识题或活动到场后领取一次；在活动有效期且有库存。不是注册即领，不绑定分享。奖励预算、合作门店、领取资格范围、账户合并后的去重
每日参与知识题正确、投票、审核通过的真实问题合计每天一次基础积分；3／7次为累计次数，不要求连续；同一任务每天不重复投票或提问领奖。提问以审核通过日计入参与；服务端时区与幂等记录

福利兑换积分扣减、库存扣减、生成券须为一个原子操作；单次操作去重；记录兑换时的门店、规则、期限快照，后续修改不改变旧券。库存台账、核销人员和客服、不可履约时返还积分的责任人

5. 可逐项体验的场景

  1. 新人礼：切换三种身份分流；完成知识题；登录演示后领取；二次访问改为查看券。
  2. 报名中活动：填写姓名与电话；确认须知；成功后显示核验码；返回不能重复报名；取消后名额释放。
  3. 满员活动、已取消活动、已结束活动：检查按钮和内容不同。
  4. 后台核验：找到进行中活动的待参加小林，核验后查看小程序积分与已到场报名。
  5. 积分兑换：确认扣分；获取券码；在后台兑换记录找到同名新券；错误码不能核销，正确码可以。
  6. 福利补货：已兑完福利补货后恢复上架；下架后小程序不再显示；历史待使用券仍保留。
  7. 管家活动：编辑草稿或未通过活动、提交；后台审核；新活动进入小程序。
  8. 管家内容：提交攻略，后台采纳后首页出现署名内容；不采纳能查看原因并修改。
  9. 共创审核：审核待处理申请，进入通过或未通过详情；通过后可查看贡献或退出。
  10. 所有列表：关键词、状态、项目筛选及空结果；所有确认弹窗：取消不写入；所有详情：只读文本，而非禁用表单。

合作签订后再确定的五件事

  1. 权益是什么：App 内哪些增值能力、适用账号、有效期、用量及限制，是否允许与已有套餐叠加。
  2. 如何采购与履约：签约与供货主体、品牌素材授权、批量采购合同、发放渠道、售后与失败补发责任。
  3. 如何领取：建议为原新人条件完成后的一次额外权益，不以外部分享为门槛；最终条件与库存由双方确认。
  4. 如何激活：由合作方提供可验证的领取入口或卡券能力；只凭点击跳转不能标记激活成功，不把合作方账号密码交给本平台。
  5. 如何保护用户：明确是否需要授权、是否涉及付费及自动续费、到期处理、使用失败处理。未确认前保持本次预告态。

正式发放阶段再扩展“可领取、待激活、已激活、已过期、发放失败”的闭环。本次未实现这些状态，不以假接口模拟真实供应商返回。
