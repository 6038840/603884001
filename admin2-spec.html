二、积分规则：从五个数字改为逐条规则

入口：积分商城 → 积分规则。按日常活跃、活动参与、内容共创、新人拉新管理。规则列表提供查询、导出、新建；每条规则拥有只读详情、编辑、发布确认、状态操作与奖励试算。

编辑区字段一期设计与校验
奖励行为规则名称；奖励行为；适用人群；每次积分；有效行为说明奖励行为含每日有效参与、活动到场、内容采纳、累计参与、首次有效咨询、线下签约成交、问卷完成。名称和说明不能为空；积分为正整数。不是通过分享按钮次数直接奖励。
范围参与项目；好友／群聊渠道默认武汉城投安家乐寓参与项目，也可选择示例单项目。推荐类行为才展示渠道。至少选一个渠道，且同一被推荐人跨渠道去重。
领取限制计算周期；周期最大领取次数；每人累计上限；累计门槛按行为匹配周期：每日、每场活动、每篇内容、每位被推荐人、每份问卷、每人。累计3／7次是有效参与的累计，不要求连续。累计上限填0表示不另设累计上限，仍受有效行为去重限制。
发放与成本发放节点；成本承担；无效处理内容通过审核后发放，咨询核实后发放，成交录入后发放。成交成本固定由安家乐寓承担。核实无效后的回收策略与余额不足策略分开设置。
时间与发布开始／结束时间；立即生效／指定时间；生效时间结束晚于开始。已启用规则编辑后只保存待发布草稿，先检查，再发布。指定时间需晚于当前时间，时间未到仍使用原生效版本；新规则没有旧版本时不提前发奖。
详情与试算条件、限制、成本、文案、发放记录；有效次数／已领次数详情采用文本、段落和状态标签，不采用置灰表单。试算显示奖励与有效计奖次数，不写入积分流水。
规则状态列表／详情操作下一步与限制
草稿详情、编辑、发布、删除发布可立即启用或进入待生效；删除确认后只移除未发布草稿。
已启用详情、编辑、停用；有修改时“发布修改”保存不改变当前发奖。停用影响新奖励，不修改已发积分。
待生效详情、取消发布到指定时间自动使用新规则；取消恢复旧生效版本，没有旧版本则回到草稿。
已停用详情、编辑、启用检查时间与奖励后再启用，不回算历史奖励。
已结束详情、复制保留原规则与发奖记录，复制为新草稿再调整；不直接编辑历史规则。

同一行为匹配多条有效规则时只取较高奖励。历史发奖记录保存实际发出的积分，不用“今天的规则”重算历史。推荐与成交的流程已演示项目／渠道匹配；规则详情和变更记录可追溯发布过程。

通用设置与预算

通用设置包含积分名称、有效期、到期提醒、10万元平台预算、积分预算测算比例、预警阈值、预算用尽处理、去重与余额不足处理；变更记录单独保留规则发布、停用和设置调整。默认每元100积分只用于讨论预算，不代表100积分可以提现1元。实际采购成本需按福利或卡券报价计入；本原型没有真实资金结算。

“问卷首次完成奖励”保留为草稿示例，默认不额外发奖；未增加日签到、游戏或复杂会员体系。积分过期通知、预算自动阻断与无效奖励追回在本版是可编辑策略，不接短信、推送或真实账户风控服务，不应当作为这些能力已上线的证据。

三、好友推荐：核实到成交，不做合同流

入口：增长运营 → 好友推荐。列表展示推荐人、被推荐人、项目、好友／群聊来源、实际奖励、状态与操作。详情补充咨询内容、核实时间、签约日期、确认人、备注和处理时间线。不同状态均有样例。

状态操作奖励与结果
已访问详情打开页面不发奖，尚无可核实咨询。
待核实详情、确认有效、标为无效有效咨询默认20积分；检查自荐与重复；无效记录选择原因，可补充说明。
有效咨询详情、录入成交成交页填写签约项目、日期、成交确认人、备注。日期不能早于咨询，也不能晚于今天。
已成交详情默认新增300积分，由运营商承担；原有咨询奖保留，不允许再次录入或发奖。
无效详情保留重复、自荐、无法联系或非真实需求的原因，不发奖。

咨询与成交各使用独立规则；若没有适用的启用规则，仍可保存业务结果，但不会生成奖励。20／300为原型样例，不是已经对外发布的承诺。直接找房咨询与推荐咨询分开，平台不代办运营商签约。

四、需求问卷：有题目，有结果，能暂停

入口：活动运营管理 → 需求问卷。保留找房需求、通勤习惯、周末生活偏好，增加草稿与已结束样例。样例答卷合计300份，可逐条查看；人物和答案为演示生成，不是真实用户调查结论。

页面字段／按钮行为
列表名称、人群、题数、收集时间、答卷数、状态、操作；关键词／状态查询、重置、导出、新建草稿、收集中、已暂停、已结束四种状态有对应记录与操作。
编辑名称、人群、开始／结束日期、介绍、封面；问题标题、单选选项；新增问题、上移、下移、删除；保存、取消、返回至少一道必填单选题，每题至少两个不重复选项；上传图片不超过3MB。有答卷后保留题目，只修改基本信息；需改题时复制问卷。
详情文本、封面、题目选项、领取条件／填写次数；预览、返回及状态对应按钮纯只读展示。每人每份问卷一次，可修改自己保存的回答，不重复计首次奖励。
结果选项分布、答卷记录；逐题人数／比例；提交人、时间、答案；翻页、导出答卷结果基于逐份演示答卷计算；本机小程序提交后会同步新增。不会把样例结果包装为真实运营成绩。

草稿：编辑／发布／删除；收集中：结果／暂停／结束；已暂停：编辑／结果／恢复／结束；已结束：结果／复制。暂停或结束后，小程序停止新填写，已提交答案可回看。新建问卷发布后出现于需求调查，不需要改首页入口。

五、豆包新人礼：礼品、卡库、领取三层

入口：新人见面礼 → 豆包流量卡。延续用户确认的豆包头像与可领取礼品，不再做筹备预告；仍保留积分商城早餐券及历史兑换。免费新人礼不混入积分商品兑换价格。

页面字段／操作状态与控制
礼品详情活动名称、活动时间、礼品名、介绍、条件、库存、展示开关、权益说明；编辑礼品、预览、返回完成一次生活知识题或首次活动到场，免费每人一张；重复点击进入已领卡片，不再减库存。
卡库卡号、批次、有效期、采购单价、状态、领取人；查询、重置、详情、作废、分页、导入卡号可发放／已发放／已使用／已过期／已作废均有样例。已领卡号不能再作废后重发给其他人。
导入弹窗批次名称、有效期、采购单价、卡号（每行一个）；导入、取消、关闭支持字母、数字、短横线；卡号长度6—40；拦截本次重复、已有重复、过期、格式错误；失败不部分导入。采购成本未定可留空，不伪造权益方报价。
作废弹窗卡号、必填原因；确认、取消仅未发放的可用卡号允许作废，减少可领取数量，保存原因。
领取记录领取人、脱敏手机号、礼品、领取时间、期限、状态；详情、导出免费领卡从可用卡库取卡；领取状态与个人券包联动。已使用／已过期／已退回记录继续保留。
使用记录卡号、期限、领取信息、使用／退回原因；标记已使用、退回豆包线上礼品不提示“六位门店核销码”。标记只记录用户已完成权益兑换，不冒充权益方激活回执；免费卡退回0积分。
卡号、人物、批次与发放都是本机演示数据。原型可领，不等于豆包官方已经提供了同名可采购产品。具体权益内容、适用账号、兑换渠道、授权与采购合同需由商务另行落实；不编造Token额度、使用天数或官方合作承诺。

六、保留功能与体验路径

原有活动9种状态、报名4种状态、福利4种状态、兑换4种状态、内容审核和共创管家仍可使用。列表查询、分页、导出、只读详情、草稿编辑、审核、原因弹窗与图片上传保留。没有为本次后台更新重新设计小程序首页、房间详情、PK下方分享入口或通勤页面。

  1. 积分规则 → 每日有效参与 → 编辑积分 → 保存 → 查看待发布修改 → 发布 → 在规则与变更记录检查结果。
  2. 好友推荐 → 待核实记录确认有效 → 有效咨询录入线下成交 → 详情检查确认人、日期与奖励 → 小程序“我的推荐”检查历史奖励。
  3. 需求问卷 → 草稿编辑 → 增加题目／排序 → 发布 → 小程序填写 → 后台查看选项分布与答卷 → 暂停并检查小程序停止填写。
  4. 新人见面礼 → 卡库导入 → 小程序领取 → 后台领取记录查看 → 小程序或后台标记使用 → 卡库核对状态。

同一个浏览器、同一个站点打开两端可联动。已有本机业务记录不会被新版清空。重置演示数据需用户主动确认。本次仅更新本地HTML原型，未发布网站、未操作生产小程序或真实业务数据库。
